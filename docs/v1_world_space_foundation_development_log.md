# V1 开发日志：世界与空间基础

日期：2026-08-09

## 目标

建立 Hearthvale 的 2D 俯视空间基础，使玩家能够进入正式场景、连续移动，并通过对应出口在世界节点之间往返。

本次实现聚焦于：

```text
世界节点 → 进入具体场景 → 场景内移动 → 从出口进入另一个世界节点
```

## 已完成内容

### 统一场景空间

- 确定使用 2D 俯视角。
- 三个正式场景统一使用 32 像素格子组织空间。
- 格子用于组织地面、墙体、障碍和出口，玩家移动保持连续。
- 室内与室外场景使用相同的世界节点和格子空间规则。

32 像素是当前场景制作采用的实际规格；它不是角色逐格移动规则，也不预设未来素材必须采用某种表现风格。

### TileMapLayer 地图表现调整

2026-08-09 将三个 Location 的地图本体迁移到 Godot 4.7.1 的 `TileMapLayer + TileSet`：

- 三个场景共同引用 `data/world_tileset.tres`。
- 每个场景使用 `Ground` 和 `Structures` 两个 `TileMapLayer`。
- `Ground` 负责无碰撞地面；`Structures` 负责墙体、边界、建筑和固定障碍。
- 两层共同使用 32×32 像素的占位瓦片图集 `assets/tiles/placeholder_tiles.svg`。
- `Structures` 中的不可通行瓦片直接使用 TileSet 物理层产生碰撞，不再存在同位置的额外障碍节点。

当前 TileSet 只包含三个场景实际使用的 19 种占位瓦片：

本次删除了以下旧地图表达：

- `GridScene._draw()` 中的地面和网格绘制。
- 三个 Location 中用于地面、道路和区域底色的 `Polygon2D`。
- 三个 Location 中全部 `GridObstacle` / `StaticBody2D` 地图节点。
- 已失去职责的 `grid_obstacle.gd`。
- `LocationExit._draw()` 中仅供开发观察的出口矩形和箭头。

当前项目仅在 `player.gd` 中保留 `_draw()`，用于玩家尚未进入正式美术制作前的临时角色视觉。它不承担任何地图表现或地图碰撞职责。

### 出口空间表现调整

2026-08-09 为现有四个出口补充了地图内的建筑入口表现：

- 酒馆前门使用上边界双格门洞，门洞格与 `FrontDoorExit` 的 `(11, 0, 2, 1)` 完全重合。
- 酒馆后门使用下边界双格门洞，门洞格与 `BackDoorExit` 的 `(17, 15, 2, 1)` 完全重合。
- 小镇街道在酒馆建筑下边界加入双格门洞，并在 `TavernDoorExit` 的 `(17, 8, 2, 1)` 上铺设对应双格门槛。
- 酒馆后院与酒馆相邻的上边界改用建筑墙体，并在 `TavernDoorExit` 的 `(11, 0, 2, 1)` 上加入双格后门门洞。

门洞和门槛瓦片可通行，周围普通墙体和建筑瓦片继续使用 TileSet 碰撞。出口常态表现完全来自 TileMapLayer，没有恢复调试箭头，也没有增加交互文字。

本次没有修改 `LocationExit` 的触发、目标场景、目标入口或场景切换机制。

### 玩家移动

- 支持 `WASD` 和方向键输入。
- 支持上下左右四方向连续移动。
- 移动时更新四方向朝向。
- 玩家会被墙体、柜台、建筑和环境障碍阻挡。
- 摄像机跟随玩家，并受当前场景边界限制。

本次没有加入跑步、体力或角色移动属性体系。

### 世界节点与连接

当前建立三个世界节点：

| 世界节点 | 主要空间内容 | 连接 |
| --- | --- | --- |
| 酒馆 | 大厅、柜台、厨房区域、墙体和家具占位 | 前门连接小镇街道，后门连接酒馆后院 |
| 小镇街道 | 道路、建筑轮廓、酒馆入口和环境障碍 | 酒馆入口连接酒馆前门 |
| 酒馆后院 | 空地、围栏、棚屋和环境障碍 | 酒馆入口连接酒馆后门 |

每个出口只记录当前切换需要的目标场景和目标入口。没有建立 Location 分类、地点标签、地图生成器、旅行系统或通用 Portal Framework。

### 运行入口与画面

- 建立项目主场景，项目现在可以从 Godot 直接运行。
- 玩家在切换地点时保持为同一个运行时对象，当前 Location 场景被替换。
- HUD 显示当前地点名称和移动提示。
- 所有场景都使用正式节点名称和连接关系，不存在单独的玩法验证场景。

## 节点连接

```text
小镇街道的酒馆入口
        ⇅
    酒馆前门

     酒馆后门
        ⇅
酒馆后院的酒馆入口
```

玩家进入目标场景后，会出现在与连接对应、且位于出口碰撞区域之外的入口位置。

## 验证记录

使用 Godot 4.7.1 完成了以下实际运行检查：

- 工程主场景能够启动并加载酒馆。
- 酒馆、小镇街道和酒馆后院均包含 `Ground` 与 `Structures` 两个 `TileMapLayer`，并引用同一个外部 TileSet。
- 三个场景均不存在旧 `StaticBody2D` 地图节点或重复的 GridObstacle 表达。
- 玩家能够连续移动并改变朝向，同时按下两个方向也不会产生对角移动。
- 摄像机中心能够随玩家移动，并继续受当前 Location 边界限制。
- 酒馆墙体、小镇建筑和后院围栏的 TileSet 碰撞能够阻挡玩家。
- 酒馆前门、酒馆后门、小镇街道的酒馆入口和后院返回门均能在实际画面中由门洞或门槛直接辨认。
- 四处门洞或门槛的瓦片坐标均与对应 `LocationExit` 触发区域一致。
- 酒馆前门可以进入小镇街道。
- 小镇街道可以从酒馆入口返回酒馆前门。
- 酒馆后门可以进入酒馆后院。
- 酒馆后院可以从酒馆入口返回酒馆后门。
- 四次切换都使用了目标场景中对应的入口位置。
- 四次切换均通过玩家实际连续移动穿过门口触发，不依赖直接调用切换逻辑。
- 酒馆、小镇街道和酒馆后院均已通过 Godot 实际渲染画面检查瓦片布局与镜头表现。
